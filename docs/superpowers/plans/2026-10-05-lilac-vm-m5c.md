# M5c Bytecode VM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `lilac-vm` crate that compiles verified LIR to a register bytecode, runs it with a safe switch-dispatch interpreter, emits/parses a portable `.lbc` text artifact, and ships a standalone `lilac-vm` binary with an interactive debugger.

**Architecture:** A new leaf crate `lilac-vm` owns the ISA, the LIR→bytecode compiler, the interpreter, the text codec, the debugger, and the runner. `lilac-target` gains a first-class VM arch (`lilacvm`); `lilac-codegen` gains a default `emit_bytecode` hook; `lilac-cli` gains `emit-vm`/`run`/`disasm`. No LLVM is linked by the VM path.

**Tech Stack:** Rust (stable, edition 2021), std only, `unsafe_code = "forbid"`, `clippy::pedantic` deny, no `serde`. `inkwell`/`llvm-sys` stay confined to `lilac-codegen-llvm`.

**Spec:** `docs/superpowers/specs/2026-10-05-lilac-vm-m5c-design.md`

## Global Constraints

- Stable Rust, edition 2021; std only; no new runtime dependency; no `serde`.
- `unsafe_code = "forbid"` and workspace lints (`clippy::all`/`pedantic` deny) apply to every new crate/module.
- No `unwrap`/`expect`/`panic!` on user input; `lilac_error::bug!` is only for internal invariants (ICE).
- `inkwell`/`llvm-sys` never linked outside `lilac-codegen-llvm`; `lilac-vm` must be LLVM-free.
- TDD per task (failing test first); one commit per task.
- Gates before every commit: `cargo fmt --check`; `cargo clippy --workspace --all-targets -- -D warnings`; `cargo test --workspace`.
- Snapshots are LF-only, no BOM; generated via .NET `Process` stdout capture + `WriteAllText` with `UTF8Encoding($false)`, never shell redirect.
- VM target triple: `lilacvm-unknown-none`; `#bit_native` = 64; `#byte_buffer` size = 16; `format_args` piece stride = 16.
- `.lbc` version string: `0.1`.

## Review Focus

Each line is pinned by a test in the owning task (noted in parentheses):

1. A program with no `main` and no export root must fail with a clean "no entry point" error, never a panic (Task 5).
2. A call into an `extern` (bodyless) function must produce a clean VM runtime error, never a crash (Task 8).
3. Out-of-range `ref` arithmetic (`@ptr_add`/`load`/`store` past the arena) must trap with a diagnostic, never panic (Task 6).
4. Unbounded recursion must hit a VM call-depth cap and report it, never overflow the host stack (Task 5).
5. A `.lbc` with an unsupported version or a non-VM target must be rejected by the runner with exit 2 and a clear message (Task 11).
