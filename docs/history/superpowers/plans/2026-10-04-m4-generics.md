# M4 Generics + Generic Errors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Monomorphize duck-typed generics (functions, objects, methods; value-based and static `T.method()`) to concrete HIR, and render rustc-style use-site errors for unsatisfied instantiations.

**Architecture:** HIR specialization inside `lilac-typeck` (Approach A). `lilac-ty` gains `TypeKind::{Param, Instance}` plus `intern_instance`/`substitute`/`mangle`; `lilac-resolve` records declaration generic-param names; `sigs` builds template signatures and interns applied types (arity `E044` before interning); `check_bodies` instantiates on first reference (memo/poison/depth/cycle), specializing by substitution and running the existing concrete checker, then re-attributing captured diagnostics to the call site. `lilac-lower`/`lilac-const`/`lilac-ir`/the verifier see concrete types only.

**Tech Stack:** Rust (std only), `lilac-*` workspace crates, `cargo fmt`/`clippy`/`test`, `emit-ir --check` snapshots.

**Spec:** `docs/superpowers/specs/2026-10-04-lilac-rust-rewrite-m4-design.md`

## Global Constraints

- Gates after every task: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` all green.
- Frontend crates never import `inkwell`/`llvm-sys`; verified IR stays generic-free and concrete.
- No `unwrap`/`expect`/`panic!` on user input; `lilac_error::bug!` for ICEs only.
- Rust std only; no new crates.
- TDD per task; one commit per task; a `docs/errors/E0xx.md` doc for every new code.
- Version bump `SPEC.md` for normative changes; `emit-ir --check` snapshots stay LF and byte-stable.
- Existing behavior must not regress: M0–M3 suites stay green.

## Review Focus

- **Generic-argument arity**: `GenObj[]`, `GenObj[@bit8,@bit16]` on a 1-param decl, and `gen_function()` must be `E044`, never a panic or a silently-built instance.
- **`Param` leakage**: a template `Param` must never appear in `HirProgram`/LIR; concrete output must be fully substituted.
- **Missing member under both receiver forms**: `value.get()` (value-based) and `T.get()` (static) with no member must give a use-site `E042`, not an internal/def-site error.
- **Non-termination**: growing/recursive instantiations must stop (depth cap → `E051`), never hang.
- **Never-instantiated generics**: an unused generic declaration must compile silently and produce no IR item.
