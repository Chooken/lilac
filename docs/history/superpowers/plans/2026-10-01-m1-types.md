# M1 Types (Non-Generic) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `resolve` + `ty` + `typeck` check non-generic objects/functions/literals/calls so `lilac check` passes the 4 port files and rejects a blanket-generic hook with `E052`.

**Architecture:** Three passes over the M0 AST, orchestrated by `lilac-driver`: `resolve::collect` builds the item/member tables (two-phase, so `get()` forward-calls resolve), `typeck::collect_sigs` resolves type names and builds func/hook/conversion tables, `typeck::check_bodies` checks statements with expected-type threading for number literals and `@truncate`-family intrinsics. Typed HIR stays a stub (no M1 consumer; M2 lowering builds it).

**Tech Stack:** Rust, std only (no new dependencies, no new crates).

**Spec:** `docs/superpowers/specs/2026-10-01-lilac-rust-rewrite-m0-design.md` (M0 record + §6 gap log), `RUST_REWRITE_PLAN.md` §7 M1 bullet, `SPEC.md` §1/§2/§8, `IR_SPEC.md` (header only).

## Global Constraints

- Workspace lints stay `deny(all + pedantic)` with the existing three allows; `cargo fmt --check`, `clippy -D warnings`, `cargo test` green after every task.
- No `unwrap`/`expect` on user input; `bug!()` for internal invariants only.
- Frontend crates never import `inkwell`/`llvm-sys` (CI grep gate).
- No new crates and no new external dependencies in M1.
- TDD per task: failing test first, watched fail, minimal code, full suite green.
- One commit per task.
- New `E0xx` codes are frozen once documented in `docs/errors/<CODE>.md` (good/bad example, rustc error-index habit).
- `emit-ir` in M1 prints the version header only; full IR bodies wait for the M2 printer. The 4 `.lir` snapshots therefore pin the header contract, not lowering.

## Review Focus

Uncovered inputs most likely to bite, each pinned to its owning task:

1. Mismatched assignment shows only one side → user cannot tell which side is wrong. Expect both `expected` and `found` every time (Task 4 test `mismatch_shows_both_sides`).
2. Conversion chains (`@bit32 -> @bit16 -> @bit8` with only adjacent bindings) must NOT chain in v1 → `E043`, not silent success (Task 5 test `conversion_does_not_chain`).
3. Overflowing literals (`0x1FF` into `@bit8`) are NOT range-checked until M3 `E060` → accepted today; pin the lax behavior so M3 tightens it deliberately (Task 4 test `overflowing_literal_waits_for_m3`).
4. A local shadows a function name → later uses resolve to the local, and calling it is `E022` (Task 4 test `locals_shadow_globals`).
5. `==` across widths (`@bit8 == @bit32`) → `E010`; identical base `TypeId`s (after deref) compare, never convert (Task 4 test `equality_needs_same_width`).

### Task 4: Body checking core (lets, calls, literals, refs, ==)

**Files:**
- Create: `crates/lilac-typeck/src/check.rs`
- Modify: `crates/lilac-typeck/src/lib.rs` (declare `mod check;`, re-export `check_bodies`)
- Test: unit tests in `crates/lilac-typeck/src/check.rs`
- Create: `docs/errors/E010.md`, `docs/errors/E021.md`, `docs/errors/E022.md`, `docs/errors/E024.md`, `docs/errors/E027.md`

**Interfaces:**
- Consumes: Tasks 1–3 plus `resolve_type`; full intrinsic table from Task 3.
- Produces (used by Task 6): `check_bodies(program: &Program, module: &Module, sigs: &Sigs, types: &mut Types, diags: &mut Diags)`.

Rules (all errors carry both spans — annotation span + value span — per Review Focus 1):
- Locals: params + return slots + `let` names in one function scope; initializer checks BEFORE binding (so `get: @bit32 = get()` calls the function); later uses see the local (shadowing test).
- `let name: T = v`: `v` checks with `expected = T`; mismatch → `E010`.
- Number literal: type = expected bit type; non-bit or missing expected → `E024`. `Str` is always `@byte_buffer`; `Char` always `@bit32`.
- `Ident`: local → its type; item → its `DefId` must be a value (calling it is Task 4, using a function AS a value → `E021`); unknown → `E021`.
- `Tag`: must have expected enum type with that variant, else `E010`.
- `RefOf(v)`: `v` must be `Ident`/`Member` place, else `E010`; type = `ref T`.
- Assign: `ref` LHS auto-derefs (checks against underlying); plain LHS exact.
- Calls: callee `Ident` → user fn/hook/intrinsic else `E021`; callee `Member` → `E030` (M2 method calls); arg count → `E022`; each arg checks with `expected = param type`; 0-return call in value position → `E022`; call-as-statement with returns → `E022`.
- Intrinsics: `Arith` needs all-bit-same-`T` operands (literals take the unified width from siblings-or-expected, else `E024`) and returns `T`; `Cmp` same-`T` in, `@bit8` out; `AsInt/AsFloat` need `@byte_buffer` in and bit expected-out else `E024`; `SizeOf` any in → `@bitNative`; `Truncate/ExtendZero` bit in → expected bit out else `E024`; `LoadU8/StoreU8/Memcpy/ByteBuffer*/FormatArgs*` per SPEC §3 shapes (`ref` params need ref-typed args, no auto-ref); `CompileError` → `E030` (liveness is M2 folding).
- `==`: both sides auto-deref to identical base `TypeId` (bit or same object), no conversions, result `@bit8`; else `E010` (covers Review Focus 5).
- `return`: every named slot assigned ≥ once in the body (flow-insensitive), else `E027` at the slot span.
- `If/Loop/Match/IfValue/FString` → `E030` naming the construct and its milestone (M2/M3).
- Overflow (`0x1FF` into `@bit8`) passes unchecked (M3 `E060` tightens; test pins current acceptance).
