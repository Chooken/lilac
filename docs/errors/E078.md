# E078: 128-bit float arithmetic

No supported target has 128-bit float instructions, and the software
routines LLVM would call in their place (`__addtf3`, `__multf3`, …) are
not linked. So arithmetic, negation and ordered comparisons (`<`, `<=`,
`>`, `>=`) on an `@fbit128` are an error where they are reachable:

```text
error[E078]: 128-bit float arithmetic is not available on `x86_64-unknown-linux-gnu`
  --> main.lilac:2:11
   |
 2 |     sum = @f_add_128(a, b)
   |           ^^^^^^^^^^^^^^^^ an operation on an `@fbit128`
   |
   = note: reached from:
             at add (main.lilac:2:11)
               at main (main.lilac:7:13)
   = help: an `@fbit128` can be stored, copied and compared with `==`; compute in `@fbit64`
```

An `@fbit128` itself is fine: literals (rounded once, exactly), storing,
copying, and `==`, which compares bits. Arithmetic on literals alone folds
while compiling, exactly, so `x: @fbit128 = 1.0 / 3.0` is fine too.

Like `E035`, only live operations count: one in a function nothing
reachable calls, or in the dead arm of a constant condition, is never
reported.
