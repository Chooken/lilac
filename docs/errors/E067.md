# E067: type is larger than the target allows

No structure can be larger than the target's `isize::MAX` bytes: 2^31 − 1 on
a 32-bit target, 2^63 − 1 on a 64-bit one, so every offset into it fits a
signed pointer-width integer. Every concrete structure, either and array type
is laid out for the target (as the C struct or array with the same
fields) when it is first used, and one that would be larger is this
error. It points at the field, or the array length, where the size
crossed the limit, and says the size reached there.

A generic function or type that builds such a type for some arguments
fails for those arguments with `E042`; its template, checked with its
parameters unknown, is never an error, since its size is unknown.

Bad:

```lilac
Big: structure {
    a: @array(@array(@bit64, 0xFFFFFFFF), 0xFFFFFFFF)
}
```

```text
error[E067]: type `@array(@array(@bit64, 4294967295), 4294967295)` is larger than the target allows
 --> main.lilac:2:43
  |
2 |     a: @array(@array(@bit64, 0xFFFFFFFF), 0xFFFFFFFF)
  |                                           ^^^^^^^^^^ this length makes the array 147573952520956936200 bytes
  |
  = note: a structure on `x86_64-unknown-none` is at most 9223372036854775807 bytes
```

On a 32-bit target a field can cross it too:

```lilac
Big: structure {
    a: @bit64
    b: @array(@bit8, 0x7FFFFFF9)
}
```

```text
error[E067]: type `Big` is larger than the target allows
 --> main.lilac:3:5
  |
3 |     b: @array(@bit8, 0x7FFFFFF9)
  |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^ this field brings `Big` to 2147483649 bytes
  |
  = note: a structure on `i686-unknown-linux` is at most 2147483647 bytes
```

Good: keep large data behind a `ref` and allocate it at run time, in
pieces the target can address.
