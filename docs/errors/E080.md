# E080: a scoped value outlives what it borrows

A scoped value (a `scoped structure`, such as a view) holds the address
of something it does not own. The compiler tracks which of the
function's own variables each scoped value borrows from: `ref x` of a
variable `x`, and every call that returns a scoped value borrows from
the variables its `ref` and scoped arguments borrow (a method call
`list.view()` borrows `list`). A `ref` parameter or a `ref` variable
borrows nothing the function owns: what it points at lives elsewhere.

A scoped value must not outlive what it borrows:

- it cannot be returned (set into an out) while it borrows a variable
  of the function, which drops when the function returns;
- it cannot be stored through a `ref` (`self.view = view`) while it
  borrows one;
- a scoped variable cannot be set to a value borrowing a variable that
  drops before it: one declared in an inner block, or later in the same
  block;
- it cannot be used after a variable it borrows was moved out with
  `@move`.

Bad:

```lilac
Data: structure {
    value: @bit32
}

View: scoped structure {
    data: ref Data
}

look: function (data: ref Data) view: View {
    view = View { data = data }
}

leak: function () view: View {
    data: Data = Data { value = 0x1 }
    view = look(ref data)
}
```

`data` drops when `leak` returns, so the view would point at nothing.

Good:

```lilac
leak: function (data: ref Data) view: View {
    view = look(data)
}
```

The view borrows from the caller's `Data`, which outlives the call.
