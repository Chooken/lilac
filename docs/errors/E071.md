# E071: a value cannot be formatted

An f-string formats each hole through the `@format` hook for the hole's
type and the format's writer type `W`:
`@format: function (value: ref T, out: ref W) nothing`. Like every hook it
is found by its exact signature, with no conversion search. A hole whose
type has no such hook cannot be formatted, and neither can a value in an
`@format_args(W)` slot, which is the one-hole format `$"{value}"`.

Bad (`Point` has no `@format` for `Out`):

```lilac
Out: object {}

Point: object {
    x: @bit32
}

show: function (text: @format_args(Out)) nothing {}

main: function () nothing {
    point: Point = Point { x = 0x1 }
    show($"at {point}")
}
```

```text
error[E071]: `Point` cannot be formatted into `Out`
  --> main.lilac:11:16
   |
11 |     show($"at {point}")
   |                ^^^^^ no `@format` for `Point`
   |
   = help: add `@format: function (self, out: ref Out) nothing` to `Point`
```

For an object or enum declared in source, the editor offers that as a
quick fix, inserting an empty hook into the type. Any other type gets
the free-standing form: `define one: @format: function (value: ref T,
out: ref W) nothing`.

Good (the type says how it is written):

```lilac
Out: object {}

Point: object {
    x: @bit32

    @format: function (self, out: ref Out) nothing {}
}

show: function (text: @format_args(Out)) nothing {}

main: function () nothing {
    point: Point = Point { x = 0x1 }
    show($"at {point}")
}
```

Anyone can add a `@format` for a type they do not own, builtins included.
In a generic body the hole's type may depend on a parameter: a failing
instance is then `E042` at the use that made it.
