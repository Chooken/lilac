# E079: cannot move a value a reference was taken to

A value that cannot be copied (its type has `@on_drop` and no
`@on_copy`) moves when it is used by value. Once a `ref` to a variable,
or to a field of it, has been taken, that move would leave the
reference pointing at a place that no longer owns anything, and whoever
the value moved to may already have freed what it held. So a variable
that was borrowed never moves implicitly.

Borrowing a variable means taking its address:

- `ref a` or `ref a.field`;
- calling a method on it whose receiver is `self` (bare `self` is a
  `ref`), or an operator hook that takes a `ref`;
- an f-string hole, `$"{a}"`;
- a by-reference capture, `match a { .Some -> v: ref T … }`.

A reference has no lifetime the compiler can see, so a variable stays
borrowed until the end of its scope, even after it is set again. Only
the paths that took a `ref` count: a variable borrowed in one branch
can still move in the other.

Bad:

```lilac
Handle: object {
    id: @bit32

    @on_drop: function (self) nothing {
    }
}

keep: function (handle: Handle) nothing {
}

main: function () nothing {
    handle: Handle = Handle { id = 0x1 }
    first: ref Handle = ref handle
    keep(handle)
}
```

```text
error[E079]: cannot move `handle` implicitly: a reference to `handle` was taken
  --> main.lilac:14:10
   |
13 |     first: ref Handle = ref handle
   |                         ---------- a reference to `handle` is taken here
14 |     keep(handle)
   |          ^^^^^^ `Handle` cannot be copied, so this would move `handle`
   |
   = note: a `ref` may still point at `handle`, so it moves only by `@move`
   = help: write `@move(handle)` if no reference to `handle` is used after this
```

Good: say the move is meant, once nothing uses the reference again.

```lilac
main: function () nothing {
    handle: Handle = Handle { id = 0x1 }
    first: ref Handle = ref handle
    keep(@move(handle))
}
```

Or give the type an `@on_copy`, so a use copies it and the reference
still sees a live value.
