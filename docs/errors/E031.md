# E031: live `@compile_error` reached

A `@compile_error("message")` call survived constant folding and global
dead-code elimination: its function is reachable from `main` or an `--export`
root (through a direct call or a taken function address), so compilation stops
with the author's message. Dead `@compile_error` calls vanish silently — both those
in branches proven unreachable by constant conditions and those in
functions nothing reachable calls (an uncalled function or an unused hook).
Only live ones report.

```text
error[E031]: boom
  --> main.lilac:6:9
   |
 6 |         @compile_error("boom")
   |         ^^^^^^^^^^^^^^^^^^^^^^ live `@compile_error` here
```

Move the call behind a non-constant condition, or delete the code that
keeps it alive.

When the condition guarding the call is computed by a function call, folding
evaluates that call at compile time within a step and depth budget. If the
budget runs out, the condition stays undecided and the error is reported with
a note saying so; simplify the guard (or write it as a `=>` expression) so it
folds.
