# E043: missing conversion

No single `@conversion(from → to)` bridges the value to the expected type.
Conversions apply left-to-right only after an exact match fails, take exactly
one step (no chains), and for binary operators anchor on the left: only the
right side converts toward the left. `==` never converts.

Bad (no binding in scope):

```lilac
main: function () nothing {
    a: @bit32 = 0x1
    b: @bit8 = a
}
```

```text
error[E043]: no conversion from @bit32 to @bit8
  --> main.lilac:3:15
   |
 3 |     b: @bit8 = a
   |               ^ conversion attempted here
```

Good (declare the one step):

```lilac
@conversion: function (from: @bit32) to: @bit8 {
    to = @truncate(from)
}

main: function () nothing {
    a: @bit32 = 0x1
    b: @bit8 = a
}
```

An explicit `as` cast needs the same single step; a typed operand with no
`@conversion` to the target type is `E043`:

```lilac
main: function () nothing {
    a: @bit8 = 0x1
    b: @bit16 = a as @bit16
}
```

```text
error[E043]: no conversion from @bit8 to @bit16
  --> main.lilac:3:17
   |
 3 |     b: @bit16 = a as @bit16
   |                 ^
   = conversion attempted here
  --> main.lilac:3:22
   |
 3 |     b: @bit16 = a as @bit16
   |                      ^^^^^^ expected `@bit16` here
```

When the value's type has methods that take only `self` and give the
target type, the error names them, since a type that offers no exact
`@conversion` usually converts with a method whose name says what it
loses. On an `as` after a name, call or member, each one that cannot fail
is also a fix that replaces the `as`:

```lilac
using Standard

main: function () nothing {
    count: Int64 = 5
    ratio: Float64 = count as Float64
}
```

```text
error[E043]: no conversion from Standard.Int64 to Standard.Float64
 --> main.lilac:5:22
  |
5 |     ratio: Float64 = count as Float64
  |                      ^^^^^    ------- expected `Standard.Float64` here
  |                      |
  |                      conversion attempted here
  |
  = help: `Standard.Int64` converts to `Standard.Float64` with a method: `to_float64_rounded()`
  = help: replace the `as` with `.to_float64_rounded()`
```

A negative literal is the literal's magnitude negated by the expected
type's `@negate`, so for a numeric type with no `@negate` (an unsigned
integer) it is `E043` too:

```lilac
using Standard

main: function () nothing {
    byte: Uint8 = -1
}
```

```text
error[E043]: no @negate for Standard.Uint8
 --> main.lilac:4:19
  |
4 |     byte: Uint8 = -1
  |                   ^^ Standard.Uint8 has no negative values
  |
  = help: `-` needs a `@negate: function (value: Standard.Uint8) Standard.Uint8` hook
```
