# E020: duplicate definition

Two definitions share one name in one scope. Signatures must stay unique, so
the second definition is the error and the first binding wins.

Bad:

```lilac
get: function () result: @bit32 {
    result = 0x1
}

get: function () result: @bit32 {
    result = 0x2
}
```

```text
error[E020]: duplicate definition of `get`
  --> main.lilac:5:1
   |
 5 | get: function () result: @bit32 {
   | ^^^ redefined here
   |
note: main.lilac:1:1 first defined here
```

Good (rename one of them):

```lilac
get_one: function () result: @bit32 {
    result = 0x1
}

get_two: function () result: @bit32 {
    result = 0x2
}
```

The same rule covers duplicate `@conversion` pairs (`FAILS_conversion.lilac`)
and duplicate object members. Top-level hooks may overload with distinct
signatures; object-member hooks may not (same name always reports `E020`
there).
