# E075: `lilac.toml` is not TOML that Lilac reads

`lilac.toml` is written in TOML 1.0, less what no setting takes: numbers,
dates and times, multi-line strings (`"""`, `'''`) and arrays of tables
(`[[…]]`). The rest is a mistake in the TOML itself: a string its line
ends inside, an escape TOML does not have, a character where a key or a
value should be, a key with no `=` or no value, a key or table defined
twice, or arrays and inline tables nested more than 32 deep. A
`lilac.toml` that cannot be read at all is this error too.

Every mistake in the file is reported, and Lilac reads no setting from it
until they are all fixed.

Bad:

```toml
[libraries]
Util = "C:\libs"
```

```text
error[E075]: invalid escape `\l` in a string
 --> lilac.toml:2:11
  |
2 | Util = "C:\libs"
  |           ^^
  |
  = help: write `\\` for a backslash, or use a 'literal string', which has no escapes
```

In a `"basic string"`, `\` starts an escape: `\"`, `\\`, `\b`, `\t`,
`\n`, `\f`, `\r`, `\uXXXX` and `\UXXXXXXXX`.

Good: write the path with `/`, or in single quotes, where `\` is just a
character:

```toml
[libraries]
Util = 'C:\libs'
```

A key is defined once. A table a `[header]` defines can be added to only
under that header, and an inline table (`{ … }`) or an array is complete
once it is written:

```toml
[build]
mode = "release"

[build]          # E075: `build` is defined twice
```
