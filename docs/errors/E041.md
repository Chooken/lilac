# E041: signature mismatch

A call through a duck-typed requirement uses a member whose declared
signature does not match the use: wrong arity, wrong parameter count toward a
return slot, or a `ref`-vs-value receiver shape. The diagnostic points at the
call site and names the requirement that failed. (Wrong argument *count* on a
plain call remains `E022`; a plain type mismatch remains `E010`/`E043`.)

Bad:

```lilac
gen[T]: function () out: @bit32 {
    out = T.get(0x1)
}

Object: object {
    get: function () result: @bit32 {
        result = 0x1
    }
}

main: function () nothing {
    x: @bit32 = gen[Object]()
}
```

```text
error[E041]: `get` on `Object` takes 0 arguments, but 1 was supplied
  --> main.lilac:2:11
   |
 2 |     out = T.get(0x1)
   |           ^^^^^^^^^^ signature mismatch
```

Good (call it the way the object declares it):

```lilac
gen[T]: function () out: @bit32 {
    out = T.get()
}

Object: object {
    get: function () result: @bit32 {
        result = 0x1
    }
}

main: function () nothing {
    x: @bit32 = gen[Object]()
}
```
