# E026: private member

An `structure` member declared inside a `private { … }` block is usable only from
its structure's namespace (the folder that declares the type) and the namespaces
inside it, the same reach as a top-level `private` item. Anywhere else the
member is found but gated: the error points at the access and at the
declaration. Fields, instance and static functions, constants and nested
members are all gated the same way, and nested `private` blocks flatten.

So types that work together, such as `Shared` and `Weak`, can live in one
folder and build and read each other's private fields, while code outside the
folder cannot.

A namespace-private item is different: `private` at file top level excludes an
item from `using`, so an importer sees an *unresolved* name (`E021`), not
`E026`.

Bad (`things/object.lilac` and `main.lilac`, in the project's root folder):

```lilac
// things/object.lilac
Object: structure {
    member: @bit8

    private {
        secret: function (instance: ref Object) result: @bit8 {
            result = instance.member
        }
    }
}
```

```lilac
// main.lilac
using things

main: function () nothing {
    variable: Object = Object {
        member = 0x1
    }

    value: @bit8 = variable.secret()
}
```

```text
error[E026]: `secret` is a private member
  --> main.lilac:9:20
   |
 9 |     value: @bit8 = variable.secret()
   |                    ^^^^^^^^^^^^^^^ accessed from outside its structure's namespace
   |
  ::: things/object.lilac:5:9
   |
 5 |           secret: function (instance: ref Object) result: @bit8 {
   |  _________-
 6 | |             result = instance.member
 7 | |         }
   | |_________- declared private here
   |
   = note: only code in `things` and the namespaces inside it can use it
```

Good (call it from code in `things`, or make it public):

```lilac
// things/object.lilac
Object: structure {
    member: @bit8

    secret: function (instance: ref Object) result: @bit8 {
        result = instance.member
    }
}
```
