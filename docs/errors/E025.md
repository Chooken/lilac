# E025: module load error

The folder loader could not build the compilation unit. It fires when:

* a `using A.B` target (`<root>/A/B`) is missing or is not a directory;
* the root folder cannot be read;
* a `*.lilac` file in a loaded folder cannot be read.

The headline names the offending path, and a failed `using` points at the
directive. A `using` inside a `private { … }` block is still honored, so a
missing target there is also `E025`.

Bad:

```lilac
// main.lilac
using missing

main: function () nothing {
}
```

```text
error[E025]: cannot find module folder `missing`
```

Good (create the folder, or fix the root-relative path):

```lilac
using util       // <root>/util/ must exist

main: function () nothing {
}
```

The same code covers the loader's other failures, with a message naming the
path: `cannot read module folder <root>` for an unreadable root and
`cannot read module file <path>` for an unreadable source. A file's parent is
never treated as a project root; `using` paths resolve from the root folder
selected on the command line (see `SPEC.md` §6).
