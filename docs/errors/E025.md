# E025: module load error

The folder loader could not build the compilation unit. It fires when:

* a `using A.B` target (`<root>/A/B`) is missing or is not a directory;
* the root folder cannot be read;
* a `*.lilac` file in a loaded folder cannot be read;
* a folder already loaded is reached again by a second path: a link (a
  symbolic link or a Windows junction) to it, such as `A/B` leading back
  to `A`, or two libraries mounted at one folder;
* a `using` names a library vendored in the project by its folder's path
  in the project (`using vendor.Util` while `vendor/Util` is mounted as
  `Util`).

The headline names the offending path, and a failed `using` points at the
directive. A `using` inside a `private { … }` block is still honored, so a
missing target there is also `E025`.

Bad:

```lilac
// main.lilac
using missing

main: function () nothing {
}
```

```text
error[E025]: cannot find module folder `missing`
```

Good (create the folder, or fix the root-relative path):

```lilac
using util       // <root>/util/ must exist

main: function () nothing {
}
```

The same code covers the loader's other failures, with a message naming the
path: `cannot read module folder <root>` for an unreadable root and
`cannot read module file <path>` for an unreadable source. A file's parent is
never treated as a project root; `using` paths resolve from the root folder
selected on the command line (see `SPEC.md` §6).

A folder is loaded once, by its first path. A link back up the tree would
otherwise load the same files again at every level, so the second path is
reported (at its `using`, when one reached it) and the walk stops there.
With `A/B` a link to `A`:

```text
error[E025]: folder `A.B` is `A` again (through a link)
  = note: both paths lead to one folder, which loads once, as `A`
```

Remove the link, or move what both paths should share into a folder of
its own and `using` that.

Two paths without a link (two libraries mounted at one folder) read the
same, without "(through a link)".

A library may live inside the project (`--lib=Util=proj/vendor/Util`, or
`"libraries": { "Util": "vendor/Util" }` in `lilac.json`). It loads once,
under its mount name, and the project's own walk skips its folder. A
`using` must name it by that mount name:

```text
error[E025]: folder `vendor.Util` is mounted as library `Util`
  = note: a library loads once, under its mount name `Util`
  = help: write `using Util`
```
