# W020: operator-type-change (warning)

A user hook changes an operator's type shape. This is a warning, not an
error: the program still checks and `lilac check` still exits 0. Silence
it with `lilac check --allow operator-type-change`.

Silent (no warning):

- Arithmetic (`@add`, `@sub`, `@mul`, `@div`, `@mod`, `@negate`) where
  every parameter and return is a by-value `@bit` variant (mixed widths
  are fine: `@add(@bit8, @bit32) -> @bit32` is silent).
- Comparisons (`@less_than`, `@greater_than`, `@less_than_or_equal`,
  `@greater_than_or_equal`) keeping the `(T, T) -> @bit8` shape for any
  single type `T`.

```text
warning[W020]: operator `@add` changes type shape
  --> main.lilac:5:1
   |
 5 | @add: function (lhs: Matrix, rhs: Matrix) result: @bit32 {
   | ^^^^ custom shape here
```

Good (silent): `@add: function (lhs: @bit8, rhs: @bit32) result: @bit32`
(all `@bit`). Good (silent): `@less_than: function (lhs: Matrix, rhs: Matrix) result: @bit8`
(`(T, T) -> @bit8` kept).
