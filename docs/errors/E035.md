# E035: `@linux_syscall` on a target without system calls

`@linux_syscall` is the Linux system-call instruction, so it exists only on
Linux for x86-64 and aarch64. A reachable `@linux_syscall` on any other
target is an error, and so is `@linux_thread_clone`, which starts a thread
with Linux's `clone`:

```text
error[E035]: `@linux_syscall` is not available on `x86_64-pc-windows-msvc`
 --> main.lilac:2:9
  |
2 |     r = @linux_syscall(0x27, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0)
  |         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ no system-call instruction on this target
  |
  = note: reached from:
            at call (main.lilac:2:9)
            at main (main.lilac:5:22)
  = help: `@linux_syscall` needs Linux on x86-64 or aarch64; choose another arm with `@builtin.Target`
```

Like `E031`, only live calls count: a `@linux_syscall` in a function
nothing reachable calls, or in the dead arm of a constant condition, is
never reported. Platform code keeps each `@linux_syscall` in a Linux-only
arm and calls the platform's own interface (an `extern`) elsewhere:

```lilac
get_current_process_id: extern "GetCurrentProcessId" function () id: @bit32

process_id: function () id: @bit_native {
    match @builtin.Target.os {
        .Linux => id = @linux_syscall(0x27, 0x0, 0x0, 0x0, 0x0, 0x0, 0x0)
        .Windows => id = @extend_zero(get_current_process_id())
        .MacOs => @compile_error("no process ids on macOS yet")
        .None => @compile_error("no process ids without an OS")
    }
}
```
