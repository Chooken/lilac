# E028: unsupported `extern` declaration

An `extern` (or `export`, or C function type) declaration the platform C ABI
cannot represent. Each parameter and the single return must be a bit integer
(`@bit8`/`@bit16`/`@bit32`/`@bit64`/`@bit_native`) or a float
(`@fbit16`/`@fbit32`/`@fbit64`/`@fbit128`), any `ref T` (an opaque pointer),
or an object or enum, which passes by value as its C struct does. An array
by value is not one (C passes none), nor is an empty object (C has no empty
struct), nor any aggregate on 32-bit Arm macOS. An `extern` may declare at
most one out place, and may not be named `main`: externs are unmangled, so
its C symbol `main` would collide with the entry point the LLVM backend
emits. The check runs before codegen, so the failure is an ordinary
diagnostic rather than a backend error.

Bad (an array by value is not a C ABI type):

```lilac
fill: extern function (bytes: @array(@bit8, 0x4)) nothing

main: function () nothing {
    fill(@array(@bit8, 0x4) { })
}
```

```text
error[E028]: `extern` parameter `bytes` has unsupported C type `[4 x #bit8]`
 --> main.lilac:1:24
  |
1 | fill: extern function (bytes: @array(@bit8, 0x4)) nothing
  |                        ^^^^^^^^^^^^^^^^^^^^^^^^^ an array
  |
  = help: C passes no array by value; pass a `ref` to it, or wrap it in an object
```

Good: `fill: extern function (bytes: ref @array(@bit8, 0x4)) nothing`, or an
object holding the array, which C takes as its struct.

Bad (more than one out place):

```lilac
pair: extern function () result: @bit32, second: @bit32

main: function () nothing {
    a: @bit32, b: @bit32 = pair()
}
```

```text
error[E028]: `extern` function `pair` declares 2 out places; at most one is allowed
  --> main.lilac:1:42
   |
 1 | pair: extern function () result: @bit32, second: @bit32
   |                                          ^^^^^^^^^^^^^^ extra out place
help: an `extern` may return at most one C value
```

Good (supported parameters and a single return):

```lilac
write: extern function (fd: @bit32, buf: ref @bit8, n: @bit_native) result: @bit_native

main: function () nothing {
    s: @byte_buffer = "hi\n"
    n: @bit_native = write(0x1, @byte_buffer_ptr(s), @byte_buffer_len(s))
}
```

Bad (an `extern` named `main` collides with the entry point):

```lilac
main: extern function () nothing
```

```text
error[E028]: `extern` function `main` conflicts with the program entry point
  --> main.lilac:1:1
   |
 1 | main: extern function () nothing
   | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   = `main` is reserved for the entry point
help: rename the `extern`; an `extern` symbol is unmangled and cannot be `main`
```

Bad (two externs link one symbol with different signatures):

```lilac
narrow: extern "abs" function (value: @bit32) result: @bit32
wide: extern "abs" function (value: @bit64) result: @bit64
```

```text
error[E028]: `abs` is declared with two different signatures
 --> main.lilac:2:1
  |
1 | narrow: extern "abs" function (value: @bit32) result: @bit32
  | ------------------------------------------------------------ first declared as `(@bit32) @bit32`
2 | wide: extern "abs" function (value: @bit64) result: @bit64
  | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ declared here as `(@bit64) @bit64`
  |
  = help: externs that share a link name must declare the same C signature
```

Identical declarations of one link name, in any namespaces, are fine: they
link as one symbol. A `ref T` is a C pointer whatever `T` is, so declarations
that differ only in pointee match.

Bad (a variadic argument with no type, or one C would promote):

```lilac
open: extern function (path: ref @bit8, flags: @bit32, ...) fd: @bit32

main: function () nothing {
    path: @bit8 = 0x0
    a: @bit32 = open(ref path, 0x0, 0x1b6)
    b: @bit32 = open(ref path, 0x0, path)
}
```

```text
error[E028]: a variadic argument needs a type
 --> main.lilac:5:37
  |
5 |     a: @bit32 = open(ref path, 0x0, 0x1b6)
  |                                     ^^^^^ this literal has no type to pass
  |
  = help: give it one with `as`, e.g. `0x1b6 as @bit32`

error[E028]: `@bit8` cannot be a variadic argument
 --> main.lilac:6:37
  |
6 |     b: @bit32 = open(ref path, 0x0, path)
  |                                     ^^^^ not passable through `...`
  |
  = help: C promotes narrow integers and floats; pass a `@bit32`, `@bit64`, `@bit_native`, `@fbit64` or a `ref`, widening explicitly with `as`
```

Good: `open(ref path, 0x0, 0x1b6 as @bit32)`.

Bad (a variadic extern as a function value; function types have no `...`):

```lilac
open: extern function (path: ref @bit8, flags: @bit32, ...) fd: @bit32

main: function () nothing {
    f: function (path: ref @bit8, flags: @bit32) fd: @bit32 = open
}
```

```text
error[E028]: cannot use variadic extern `open` as a value
 --> main.lilac:4:63
  |
4 |     f: function (path: ref @bit8, flags: @bit32) fd: @bit32 = open
  |                                                               ^^^^ function types have no `...`
  |
  = help: call it directly, or wrap it in a function with fixed parameters
```

The same code covers an unsupported **return** when there is exactly one out
place: the message names the slot and its type, and the label says why
("an array", "an empty type"). A `>1` out is reported once, at the first
extra slot, before the per-slot return check.
