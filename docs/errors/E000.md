# E000: invalid token

The source contains text that is no token: a malformed number literal
(`0x` with no digits, a digit the base does not have), an unterminated
character literal or f-string, or a character the language does not use
(a lone `$` that does not start an f-string). Lexing continues after the
bad token, so one typo is one error.

Bad:

```lilac
main: function () nothing {
    x: @bit32 = 0b102
}
```

```text
error[E000]: invalid digit in binary literal
 --> main.lilac:2:17
  |
2 |     x: @bit32 = 0b102
  |                 ^^^^^
```

Good: write the literal in a base that has its digits (`0x42`), close the
literal, or remove the stray character.
