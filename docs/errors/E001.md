# E001: syntax error

The tokens do not form a program: something is missing (`expected
expression`, `expected }`) or out of place. The parser recovers at the next
statement or item, so later syntax errors are reported too, and the type
checker still runs on what parsed (a broken piece is a poison node that
reports nothing more).

Bad:

```lilac
main: function () nothing {
    x: @bit32 = (0x1 +
}
```

```text
error[E001]: expected expression
 --> main.lilac:3:1
  |
3 | }
  | ^
```

Good: finish the expression (`x: @bit32 = (0x1 + 0x2)`).

## Nesting limit

Expressions, statements, blocks and types may nest at most 256 levels deep
(each parenthesis, call, operator in a chain, nested `if` or block is one
level). Past that the construct is reported once and skipped, rather than
running the compiler out of stack:

```text
error[E001]: nested too deeply; the limit is 256 levels
  = help: move part of it into a variable or a function
```

Good: give a part of the expression a name, or move it into a function.

## `object` and `enum`

A type is declared with `structure` or `either`; `object` and `enum` were
the keywords before them and are ordinary names now. A declaration spelled
with one is reported with the new keyword as its fix:

```text
error[E001]: `object` is not a keyword; a type is declared with `structure`
 --> main.lilac:1:8
  |
1 | Point: object {
  |        ^^^^^^
  |
  = help: did you mean `structure`?
```

Good: `Point: structure {`, and `Shape: either {` for an `enum`.
