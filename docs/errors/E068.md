# E068: too many generic instances

Every distinct `(generic function, type arguments)` a program uses is
checked and compiled on its own. A check builds at most 50,000 generic
function instances; the request for one more is this error, and nothing
further is instantiated. It names the definitions with the most instances,
from the first instance built to the latest, which shows how their
arguments grow, and the instantiation chain of the one that did not fit.

Recursion is `E051`'s, not this error's: a generic that reaches itself
again is followed depth first and stops at 64 appearances on its chain.
`E068` is for programs that never recurse but multiply, such as a chain of
generics where each level instantiates the next at more than one new
argument type: the count doubles at each level.

Bad (level `n` has `2^(n-1)` instances, so the levels add up to 131,071;
levels 2 to 15 are left out here, so the line numbers are the full
program's):

```lilac
A[T]: object {
    value: T
}

B[T]: object {
    value: T
}

level1[T]: function () nothing {
    level2[A[T]]()
    level2[B[T]]()
}

// ... level2 to level15 alike ...

level16[T]: function () nothing {
    level17[A[T]]()
    level17[B[T]]()
}

level17[T]: function () nothing {
}

main: function () nothing {
    level1[@bit32]()
}
```

```text
error[E068]: too many generic instances
  --> main.lilac:81:5
   |
81 |     level16[B[T]]()
   |     ^^^^^^^^^^^^^^^ `level16[B[A[A[A[B[A[B[A[B[B[A[A[A[A[B[@bit32]]]]]]]]]]]]]]]]` would be one too many
   |
   = note: a check builds at most 50000 generic instances
   = note: `level16` has 17233 instances, from level16[A[A[A[A[A[A[A[A[A[A[A[A[A[A[A[@bit32]]]]]]]]]]]]]]]] to level16[A[A[A[A[B[A[B[A[B[B[A[A[A[A[B[@bit32]]]]]]]]]]]]]]]]
   = note: `level15` has 16384 instances, from level15[A[A[A[A[A[A[A[A[A[A[A[A[A[A[@bit32]]]]]]]]]]]]]]] to level15[B[B[B[B[B[B[B[B[B[B[B[B[B[B[@bit32]]]]]]]]]]]]]]]
   = note: `level14` has 8192 instances, from level14[A[A[A[A[A[A[A[A[A[A[A[A[A[@bit32]]]]]]]]]]]]]] to level14[B[B[B[B[B[B[B[B[B[B[B[B[B[@bit32]]]]]]]]]]]]]]
   = note: instantiation chain: level1[@bit32] -> level2[B[@bit32]] -> ... -> level15[A[A[A[B[A[B[A[B[B[A[A[A[A[B[@bit32]]]]]]]]]]]]]]] -> level16[B[A[A[A[B[A[B[A[B[B[A[A[A[A[B[@bit32]]]]]]]]]]]]]]]] (16 frames)
```

Good: pass the varying part as a value, so one instance serves every case,
or instantiate at fewer argument types per level.

The generic functions nothing uses are checked as templates afterwards,
with a budget of their own, so unused code never takes instances from used
code.

## Why 50,000

The budget is far above what programs need and low enough that reaching it
stays fast. `lib/Standard` and the whole test suite build at most 9
generic instances in one check (18 in the template pass). Measured on
Windows x86-64, `lilac check` wall time to `E068`, process start included:

| Program | Release | Debug |
|---|---|---|
| two-way fan-out, empty bodies (17 levels) | 0.53 s | 2.0 s |
| two-way fan-out, empty bodies (20 levels) | 0.53 s | 2.0 s |
| three-way fan-out, empty bodies (14 levels) | 0.78 s | 2.9 s |
| two-way fan-out, ten-statement bodies (18 levels) | 1.3 s | 5.6 s |

At 100,000 the ten-statement case took 2.4 s in release, past the 2 s
any of these may take (`docs/robustness-plan.md`, Phase 6). Branching
recursion (`grow[T]` calling `grow[W[T]]` and `grow[V[T]]`, or three such
calls) ends with `E051` in under 0.1 s in either build.
