# E055: invalid `export`

An `export` is a function C can call: `name: export function (…) out { … }`
defines the C symbol `name` (or the link name in `export "symbol"
function …`) with the platform C ABI. Its symbol is unmangled, so the
compiler requires:

- It is a top-level function: not a method, a hook, or generic (C has one
  symbol per function and no `self`).
- Its symbol is not `main`, the program's entry point.
- No other `export`, and no `extern`, names the same symbol: an `export`
  defines it, so a second definition or a declaration of it would clash.

Its parameters and result follow the `extern` rules (`E028`): bit integers,
floats, `ref T`, or an object wrapping one of those, and at most one
result.

Bad:

```lilac
Counter: object {
    count: @bit32

    bump: export function (self) nothing {
        self.count = self.count + 0x1
    }
}
```

```text
error[E055]: an `export` must be a top-level function
 --> main.lilac:4:5
  |
4 |     bump: export function (self) nothing {
  |     ^^^^ not a top-level function
  |
  = help: export a top-level function that calls this one, under another name
```

Good:

```lilac
counter_bump: export function (counter: ref Counter) nothing {
    counter.bump()
}
```
