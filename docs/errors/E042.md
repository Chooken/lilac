# E042: unsatisfied generic requirements

A generic declaration is checked once per concrete `(declaration, type
arguments)` instance. When the specialized body uses an operation the
concrete type cannot support (a missing member, an incompatible signature, a
failed conversion), the failure is re-attributed to the **use site**: one
`E042` lists every failed requirement, with the generic's definition as a
note and every instantiating call as a `reached from:` trace. Nothing from the generic's innards leaks as a
separate error, so one bad instantiation is exactly one diagnostic.

Only failures that depend on the type arguments are `E042`. A mistake in the
body that would fail with any arguments (`y: @bit32 = 1 as @bit8`, or a
member the generic object itself lacks) is reported as its own error, once,
in the generic's own words (`GenObject[T]`), however many instances there
are.

When the failure includes a **missing member**, the primary label moves to the
failing member use inside the generic body, with the requirement phrase (for
example `missing method \`other\` on \`@bit32\``). The instantiation call site
becomes a secondary source-snippet label naming the pretty instance
(`required by instantiation of gen_function[@bit32] here`), and a `note:` spells
out the method signature the generic body requires:

```text
based on this usage, the generic body requires a method matching:
      fn other() -> T
```

A missing **field** read gets the analogous field note, with the field's type
taken from the use-site expected type:

```text
based on this usage, the generic body requires a field matching:
      data: T
```

The inferred signature uses the generic's own parameter form: receiver, argument
types, and the expected return type print as `T` when the concrete type is one
of the current instantiation's arguments (the first matching parameter wins),
otherwise concretely (for example a `Widget` return stays `Widget`). A value
receiver contributes `self: ref <receiver>` (a method's first parameter is
always `ref Self`); a bare-type receiver (`T.member()`) has no `self`. Argument
types are probed with no expected type; an unconstrained return or field type
renders `?`. Field **writes** (`value.data = expr`) are not annotated: the
target type is resolved before the written expression is checked, so no
use-site expected type is available.

When the failure has no missing member, the primary label stays at the call site
("instantiated here") and the generic definition is a note. The `reached
from:` note is a caller tree: the failing instance first, then every site
that requested it, through other generic instances, down to the ordinary
functions that started each chain. An instance whose requesters were
already listed is marked `[see above]`, and levels past five are elided
unless `--verbose`. An instance requested from several places is still one
`E042`, listing every site; in the editor each of those sites is marked
too.

Helps are emitted where the compiler can justify them: edit-distance
did-you-mean over the concrete type's members, argument arity counts,
`ref`-vs-value hints, and a discovered `@conversion`. The **`using` help is
downgraded**: v1 `using` is a single-file stub with no module table to
consult, so the compiler cannot resolve an external member and emits no
`using` suggestion (ruling R9).

Bad:

```lilac
gen_function[T]: function () out: T {
    out = T.other()
}

main: function () nothing {
    variable: @bit32 = gen_function[@bit32]()
}
```

```text
error[E042]: type `@bit32` does not satisfy `gen_function[T]` requirements
  --> main.lilac:2:11
   |
 2 |     out = T.other()
   |           ^^^^^^^^^
   = missing method `other` on `@bit32`
  --> main.lilac:6:24
   |
 6 |     variable: @bit32 = gen_function[@bit32]()
   |                        ^^^^^^^^^^^^^^^^^^^^^^ required by instantiation of gen_function[@bit32] here
note: based on this usage, the generic body requires a method matching:
      fn other() -> T
```

Good (instantiate with a type that provides the member):

```lilac
Object: structure {
    other: function () result: @bit32 {
        result = 0x1
    }
}

gen_function[T]: function () out: T {
    out = T.other()
}

main: function () nothing {
    variable: @bit32 = gen_function[Object]()
}
```
