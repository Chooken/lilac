# E060: literal value error

A literal's value cannot be represented in its target type, or a
fold-required intrinsic (`@as_int`/`@as_float`/`@size_of`) cannot be
evaluated at compile time. These are value errors, not type errors: the
type is right, the constant is not.

Three cases:

- A hex/bin literal wider than its annotated bit type
  (`x: @bit8 = 0x1FF`).
- `@as_int`/`@as_float` on a non-constant buffer (a variable rather than
  a literal), or on digits that do not parse.
- `@as_int` whose value overflows the expected bit width.

Bad (overflowing literal):

```lilac
main: function () nothing {
    x: @bit8 = 0x1FF
}
```

```text
error[E060]: value does not fit in @bit8 (max 0xFF)
  --> main.lilac:2:15
   |
 2 |     x: @bit8 = 0x1FF
   |               ^^^^^ literal overflows
```

Bad (`@as_int` must fold):

```lilac
main: function (n: @byte_buffer) nothing {
    x: @bit8 = @as_int(n)
}
```

```text
error[E060]: `@as_int` requires a compile-time-constant operand
  --> main.lilac:2:15
   |
 2 |     x: @bit8 = @as_int(n)
   |               ^^^^^^^^^^ evaluated here
```

Good (in-range literal and constant `@as_int`; the decimal `127` is a
`@byte_buffer` literal, while `0x7F` would be a bit-typed `LitLiteral`):

```lilac
main: function () nothing {
    x: @bit8 = 0xFF
    y: @bit8 = @as_int(127)
}
```
