# E060: literal value error

A literal's value cannot be represented in its target type, or a
fold-required intrinsic (`@size_of`) cannot be evaluated at compile time.
These are value errors, not type errors: the type is right, the constant is
not.

Cases:

- An integer literal that needs more bits than its target holds: a hex/bin or
  decimal literal wider than its annotated type (`x: @bit8 = 0x1FF`), a value
  past 64 bits (`0x1_0000_0000_0000_0000`), or one that does not fit the
  conversion width of a numeric object (`x: Int8 = 300`).
- A float literal past the target's maximum finite value
  (`x: @fbit16 = 100000.0`).
- `@size_of` on a value that is not a compile-time-constant typed integer.
- Decimal division or modulo by zero (`x: @bit8 = 1 / 0`), folded at compile
  time (SPEC §2).

Bad (overflowing literal):

```lilac
main: function () nothing {
    x: @bit8 = 0x1FF
}
```

```text
error[E060]: value needs 9 bits but @bit8 holds 8
  --> main.lilac:2:16
   |
 2 |     x: @bit8 = 0x1FF
   |                ^^^^^ literal overflows
```

Bad (division by zero):

```lilac
main: function () nothing {
    x: @bit8 = 1 / 0
}
```

```text
error[E060]: division by zero
  --> main.lilac:2:16
   |
 2 |     x: @bit8 = 1 / 0
   |                ^^^^^
   = in decimal literal
```

Decimal modulo by zero is the same `E060`, reading `modulo by zero`.

Good (integer and float literals in range):

```lilac
main: function () nothing {
    x: @bit8 = 0xFF
    y: @bit64 = 0x1_0000_0000
    z: @fbit32 = 3.14
}
```
