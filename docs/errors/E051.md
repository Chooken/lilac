# E051: cyclic or too-deep generic instantiation

Monomorphizing a generic reference specializes a new instance per distinct
`(declaration, type arguments)`. Self-recursion with *identical* arguments is
fine: the instance is already being built, so the reference reuses it and the
body is checked once. A chain that keeps producing *new* arguments, however,
never terminates.

Recursion is counted per definition, as rustc counts it: a generic function
may appear at most 64 times on its own instantiation chain (the instances
that requested one another, from the first use down), and a generic type may
be laid out inside itself at most 64 times. The 65th is this error. A chain
of *different* generics is never too deep, however long.

A recursive instance is checked next, so recursion is followed depth first:
a generic that requests itself at two or three new argument types per level
reaches the limit after 64 bodies, not `2^64`. Once a definition has failed,
every other recursive use of it stops there, without another error.

When each step wraps the arguments of the one before, a note shows the first
two instances, so the growth is visible.

Bad (each level nests a fresh argument, so no instance ever repeats):

```lilac
Box[T]: structure {
    value: T
}

grow[T]: function () nothing {
    grow[Box[T]]()
}

main: function () nothing {
    grow[@bit32]()
}
```

```text
error[E051]: generic instantiation is too deep (possible infinite recursion)
 --> main.lilac:6:5
  |
6 |     grow[Box[T]]()
  |     ^^^^^^^^^^^^^^ instantiated here
  |
  = note: instantiation chain: grow[@bit32] -> grow[Box[@bit32]] -> ... -> grow[Box[Box[...]]] -> grow[Box[Box[...]]] (65 frames)
  = note: the type arguments grow each time: grow[@bit32] -> grow[Box[@bit32]]
  = note: a generic may appear at most 64 times on one instantiation chain, and `grow` would appear once more
```

(Types in notes are cut with `...` past 200 characters; the last two frames
here are 64 and 65 levels deep.)

Good (self-recursion with the same arguments caches one instance):

```lilac
rec[T]: function (x: T) result: T {
    result = rec[T](x)
}

main: function () nothing {
    y: @bit32 = rec[@bit32](0x1)
}
```

A generic nothing uses is checked as a template, with its parameters left
abstract; its recursion stops at the same limit, silently, since the
arguments it would grow are unknown.

## Types nested too deeply

Laying out a type lays out every type its fields hold, recursively. Types may
nest at most 1,024 deep, distinct or not, which keeps the compiler's own
stack bounded; one more is this error, reported as "types nest too deeply to
lay out" at the field that crossed the limit.
