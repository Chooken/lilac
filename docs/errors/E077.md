# E077: a function is a value only behind `ref`

A function value is a reference to the function's code: its type is
`ref function (…) …`, and the value of a function `f` is `ref f`. A bare
`function (…)` type, like `unknown`, only exists behind `ref`, so it cannot
be the type of a local, a parameter, an out, a field, a global, a constant,
an array element, an enum payload or a generic argument. The one place a
bare function type may be written is the target of an `alias`; every use
of that alias then writes `ref Name`, as `unknown` is written `ref
unknown`.

Naming a function without `ref` (`apply(add_one, 0x1)`) is the same
mistake from the other side.

Bad:

```lilac
Step: alias function (value: @bit32) result: @bit32

Machine: object {
    next: Step
}

add_one: function (value: @bit32) result: @bit32 => @i_add_32(value, 0x1)

main: function () nothing {
    step: function (value: @bit32) result: @bit32 = add_one
}
```

```text
error[E077]: `Step` is a function type, a value only behind `ref`
 --> main.lilac:4:11
  |
4 |     next: Step
  |           ^^^^ write `ref Step`
  |
  = help: a function value is a reference to its code: add `ref`

error[E077]: a function type is a value only behind `ref`
  --> main.lilac:10:11
   |
10 |     step: function (value: @bit32) result: @bit32 = add_one
   |           ^^^^^^^^ write `ref function`
   |
   = help: a function value is a reference to its code: add `ref`

error[E077]: `add_one` is a function, a value only behind `ref`
  --> main.lilac:10:53
   |
10 |     step: function (value: @bit32) result: @bit32 = add_one
   |                                                     ^^^^^^^ write `ref` before it
   |
   = help: a function value is a reference to its code: add `ref`
```

Good:

```lilac
Step: alias function (value: @bit32) result: @bit32

Machine: object {
    next: ref Step
}

add_one: function (value: @bit32) result: @bit32 => @i_add_32(value, 0x1)

main: function () nothing {
    step: ref function (value: @bit32) result: @bit32 = ref add_one
    machine: Machine = Machine { next = step }
    two: @bit32 = machine.next(0x1)
}
```

The compiler's fix inserts each `ref`. A call through a function reference
passes no `self`: `machine.next(0x1)` calls the function the field holds.

In an object body, `step: function (…) …` with no body is a method missing
its body (`E001`), whose help points here: a field that holds a function
is a `ref function (…) …` too.
