# E032: no `main` for `@entry`

`lilac build` produces an executable, which starts in the `@entry` platform
hook. `Standard`'s `@entry` calls the program's `main`, and inside an
`@entry` body a name is looked up in the program's root namespace. So the
program needs a `main` in a file at the project root. A `main` inside another
namespace (`A.main`) is an ordinary function and does not count.

```text
error[E032]: the program has no `main`, which `@entry` calls
  --> Standard/Runtime/runtime.lilac:10:5
   |
10 |     main()
   |     ^^^^ `@entry` calls `main` here
   |
   = note: `@entry` looks names up in the program's root namespace; define `main` in a file at the project root
```

Bad:

```lilac
// lib.lilac
helper: function () nothing {
}
```

Good:

```lilac
main: function () nothing {
    helper()
}

helper: function () nothing {
}
```

Only `build` needs `main`. `check`, `emit-ir` and `emit-llvm` accept a
library without one: nothing enters it, so `@entry` is left out. A runtime
library other than `Standard` may enter the program under another name.
