# E076: a `lilac.toml` setting is unknown or has a wrong value

`lilac.toml` takes the sections `[project]`, `[build]`, `[libraries]` and
`[link]`, each with its own settings (`lilac init` writes them all, with
their defaults). A section or setting Lilac does not know is an error, not
ignored: a mistyped setting that did nothing would build the wrong program.
So is a value of the wrong type, an unknown mode or target, a project
name a file cannot have, a library name that is not an identifier, and a
folder that does not exist.

A setting with this error is left out, as if it were not written; the
others still apply.

Bad:

```toml
[build]
mode = "release"
stack_traces = true
```

```text
error[E076]: unknown setting `stack_traces` in `[build]`
 --> lilac.toml:3:1
  |
3 | stack_traces = true
  | ^^^^^^^^^^^^
  |
  = help: did you mean `stack-traces`?
```

Good:

```toml
[build]
mode = "release"
stack-traces = true
```

A library is a folder, `{ path = "folder" }`, or `{ bundled = true }` for
one installed with Lilac, and its name is the namespace it mounts as:

```toml
[libraries]
Standard = { bundled = true }
Util = "vendor/Util"
my-json = "../json"        # E076: library name `my-json` is not an identifier
Extra = { bundled = false } # E076: `bundled = false` mounts nothing
```

Folders in the manifest are relative to the folder holding it.
